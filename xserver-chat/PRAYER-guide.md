# 祈りの蓄積：設置・利用手順

平和を願う日々の祈り・実践を月ごとに記録する機能です。
宗教への入信を求めるものとして扱いません。無理のない参加を前提にします。

## 更新ファイルを設置する

`xserver-chat/updates/ku-fudo-prayer-update.zip` をダウンロードして解凍してください。

1. 更新前に、現在の `public_html/ku-fudo-chat` のプログラムと、公開領域外の `ku-fudo-private` を控えてください。データの控えは安全な手元の場所に保管します。`chat.sqlite` の控えは利用者が操作していない時間に取得してください。
2. 解凍した `ku-fudo-chat` 内の18ファイル（`.htaccess` を含む）を、`taf-design.com/public_html/ku-fudo-chat/` にアップロード・上書きします。
3. 解凍した `ku-fudo-demo` 内の `index.html` と `style.css` を、`taf-design.com/public_html/ku-fudo-demo/` にアップロード・上書きします。現在の画像と `app.js` はそのまま使います。
4. `ku-fudo-private`・`config.php`・既存のデータベースは上書きしません。ZIPには含めていません。
5. 管理者で `https://taf-design.com/ku-fudo-chat/prayer.php?manage=1` を開きます。初回アクセス時に既存データベースへ新しい表を自動追加します。会員・チャット・REDO MAILのデータを初期化しません。
6. 最新表示にならない場合はブラウザーを再読み込みしてください。

この更新ZIPは、既存のチャットとカリキュラムが設置されているサイト用です。前回のREDO MAIL更新をまだ設置していない場合も、今回の18ファイルに含まれています。
新規設置には `ku-fudo-complete.zip` と従来の初回設置手順を使ってください。

PHP 8.2以上、PDO SQLite、mbstring、HTTPSが必要です。GitHub PagesではPHP機能は動きません。
データ形式はバージョン9です。更新後に古いプログラムだけを上書きすると動かなくなるため、戻す場合はプログラムとデータベースの両方を更新前の組み合わせに戻す必要があります。更新後の報告は、古い控えには含まれません。

## 最初に管理者が行うこと

1. チャットと同じ管理者アカウントでログインします。
2. 「祈りの蓄積」→「集計・参加者管理」を開きます。
3. 「参加者の登録・変更」で、登録済み会員の「参加設定」を押します。
4. お手元の名簿と本人を照合し、参加番号と参加開始月を設定します。例：2026年8月分から集計する方は開始月を2026年8月にします。
5. 継続中の方は参加終了月を空欄にし、「利用できる」で保存します。
6. 会員登録自体がない方は、先に通常の会員登録・管理者承認を行ってください。

実際の名簿・個人名・メールアドレスはGitHubにも更新ZIPにも登録していません。参加番号は推測で割り当てず、運営で確認した番号を設定してください。番号の重複は保存時に防止します。

チャットの無料・通常会員区分、理事などの役職、やりなおし会員の有料資格と、祈りの参加設定は別です。祈りの登録だけで役職・有料資格・チャットの権限が変更されることはありません。

参加終了月を設定すると、翌月以降は未提出確認の対象から外れます。「利用を停止する」は本人の記録の閲覧・入力を止めます。過去の記録は管理者の集計に残ります。会員そのものを削除すると、その人の祈りの記録・参加設定も削除され、集計から除かれます。記録を残したい場合は削除ではなく利用停止を使ってください。

## 参加者の操作

入口： https://taf-design.com/ku-fudo-chat/prayer.php

1. いつもの会員アカウントでログインします。仮パスワードの場合は先に初回変更を行います。
2. 報告する月を確認します。最初は終了した直近の月を表示します。
3. 各項目に月の合計を入力します。実践がない項目は0にします。
4. 「内容を確認する」→「この内容で送信する」を押します。
5. 「報告を保存しました」と表示されたら受付完了です。控えメールの送信状況も表示します。

- 人類愛の祈り・大構想の祈り・回帰点の祈り・その他の祈り・全感謝の祈り：整数の回数
- 瞑想：整数の分数
- 聴く行：時間、小数第2位まで。30分は0.5時間、1時間30分は1.5時間
- 感想・気づき：任意、3,000文字以内。全角入力を強制しません。
- 全角の数字・小数点も自動で半角へ変換します。
- 月の1日〜末日の合計です。翌月1〜7日ごろの提出を目安としますが、遅れた提出も可能です。
- まだ終了していない月は提出できません。参加開始月より前・参加終了月より後も提出できません。
- 名前・メール・番号は登録情報から自動表示します。メールが違う場合はアカウント画面で修正してから報告してください。
- 「これまでの記録」から内容を確認できます。同じ月を修正すると合計は置き換わり、二重には加算されません。複数の画面から同時に更新した場合は、後の操作に再確認を求めます。
- 通信が途切れた場合は、入力内容を控えて「保存済みの記録を読み直す」で受付状況を確認してください。

カリキュラムの入口、チャット、REDO MAILにもリンクがあります。月が変わっても同じURLを使えます。通常のブラウザーの戻る操作に対応し、確認画面からは「入力に戻る」でも戻れます。

## 控えメール

送信元の初期値は `info@taf-design.com` です。初期値でよければ追加設定は不要です。銀行入金案内・REDO MAIL配信とは別の、本人が提出した報告の控えです。

変更する場合だけ、既存の非公開 `config.php` の配列内に以下を追加できます。既存項目を消さずに編集してください。

```php
'prayer_mail_from' => 'info@taf-design.com',
'prayer_mail_enabled' => true,
'chat_login_url' => 'https://taf-design.com/ku-fudo-chat/',
```

控えには対象月、名前、番号、各実践の数値、感想、更新回数、受付日時を入れ、ご本人の登録アドレスにだけ送ります。他の参加者や担当者への自動一斉送信は行いません。

PHPのメール送信機能を使います。送信処理完了はサーバーが受け付けた意味で、受信箱への到着保証ではありません。まず運営自身のアカウントで実際の受信を確認してください。開発テストでは外部に実メールを送らず、送信処理を模擬しています。

メール送信に失敗しても報告は保存します。「控えメールを再送する」で再試行できます。「送信結果は確認中」の場合は二重送信を防ぐため自動で再送しません。送信済みのメールも自動では再送しません。入力・再送は合計で1人1時間20回までに制限しています。

## 管理者の集計

- 対象月の各実践の合計、提出済み人数・未提出人数を表示します。
- 参加期間内の会員と、その月に記録が残っている会員を確認対象にします。
- 名前を押すと、その人の報告・感想・控えメールの状況を確認できます。
- 「一覧をCSVで保存する」で、提出済みと未提出の一覧をダウンロードします。UTF-8 BOM付きで、日本語のExcelでも開きやすい形式です。
- CSVを表計算ソフトで開いた際に、入力文が数式として実行されないよう処理しています。
- 個人の記録と感想は本人と管理者だけが閲覧できます。理事・理事候補という役職だけでは他人の記録を閲覧できません。管理者アカウントを渡す方は適切に選んでください。
- 記録はサーバーの `ku-fudo-private/chat.sqlite` に保存します。ブラウザーやGoogleフォームには保存しません。

これまでのGoogleフォームの回答は自動移行しません。旧回答の集計と新サイトの集計が重複しないよう、何月分から新サイトで受け付けるかを運営で決めて案内してください。

## 変更内容と検証

- データベースへ prayer_members / prayer_reports を追加（データ形式8→9）
- prayer.php / prayer.js / prayer.css / prayer-api.php / prayer-lib.php を追加
- チャット・REDO MAIL・カリキュラムの入口へリンク追加
- 会員削除時に参加設定と個人記録も削除
- PHP 8.3の一時環境で、月次報告・全角数字・単位・修正・権限・集計・CSV・メール成功失敗・既存チャット・REDO MAILを確認
- 実サーバーへの設置、実メールの受信、Googleフォームの切替は運営側で行います
